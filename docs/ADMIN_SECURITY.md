# امنیت حساب مدیر

بخش امنیت حساب مدیر نام کاربری، پایان اعتبار نشست فعلی به وقت تهران و تعداد نشست‌های فعال دیگر را نشان می‌دهد. API خصوصی و بدون cache است؛ hash رمز، شناسه یا hash نشست به مرورگر برنمی‌گردند.

تغییر رمز نیازمند رمز فعلی، رمز تازه متفاوت با طول ۱۴ تا ۵۱۲ کاراکتر و تکرار یکسان است. تأیید رمز، تغییر hash با scrypt و salt مستقل، ابطال نشست‌های دیگر و audit در یک تراکنش BEGIN IMMEDIATE قرار دارند؛ شکست هر بخش همه تغییرات را برمی‌گرداند. آزمون رقابت در دو پردازش مستقل تنها یک تغییر با رمز قدیمی را موفق می‌کند.

نشست فعلی حفظ می‌شود تا مالکیت فایل خصوصی، بازیابی سفارش و پیش‌نویس تب تغییر نکند؛ مهلت هشت‌ساعته آن تمدید نمی‌شود. خروج نشست‌های دیگر بدون تغییر رمز نیز با رمز فعلی ممکن است. نشست حساب دیگر یا مهمان تغییر نمی‌کند. رکوردهای منقضی دیگر همین حساب هم ابطال می‌شوند، ولی شمارش فقط تعداد فعال‌هاست. نبود نشست دیگر audit تکراری نمی‌سازد.

POST نیازمند مبدأ دقیق و نشست مدیر است؛ حد پنج تلاش امنیتی برای هر حساب در پانزده دقیقه دارد. GET برای هر نشست شصت بار در دقیقه محدود است. بدنه محدود، پاسخ‌ها private/no-store و خطاها فاقد رمز یا token هستند. تاریخچه account فقط نوع عملیات و تعداد نشست بسته‌شده را ذخیره می‌کند؛ رمز، hash و token ثبت نمی‌شوند.

فرم‌ها از پیش‌نویس و Web Storage استفاده نمی‌کنند و کنترل رمز پس از شروع درخواست پاک می‌شود. مدیر رمز را وارد می‌کند؛ عامل حساب واقعی را تغییر نمی‌دهد. timeout بیست‌ثانیه‌ای مشتری به معنای لغو سرور نیست؛ نتیجه قطع ارتباط نامعلوم اعلام و درخواست خودکار تکرار نمی‌شود. مرورگر یا مدیر رمز با انتخاب کاربر می‌تواند autofill داشته باشد.

بررسی: رمز اشتباه، تأیید نامعتبر، حفظ نشست فعلی/مهمان/مدیر دیگر، rollback شکست audit و رقابت دو پردازش آزموده شدند. HTTP ایزوله نیز CSRF، ورود با رمز تازه، رد رمز قدیمی، ابطال نشست، محدودیت تلاش و محرمانگی audit را تأیید کرد. تعامل دیداری مرورگر بررسی نشده است.

## بازیابی محلی در صورت فراموشی رمز

فرمان npm.cmd run admin:reset-password -- admin فقط در ترمینال تعاملی خصوصی سرور اجرا می‌شود. نام کاربری را برای تأیید می‌پرسد، سپس رمز تازه را دو بار با ورودی پوشیده می‌گیرد. رمز در آرگومان فرمان، متغیر محیط، log یا پیام چت قرار نمی‌گیرد. دیتابیس باید از قبل وجود داشته باشد؛ حساب ناشناخته ساخته نمی‌شود و ورودی/خروجی redirectشده رد می‌شوند. مسیر دیتابیس و نام حساب قبل از تأیید نمایش داده می‌شوند؛ در صورت DATABASE_PATH سفارشی، همان مقدار محیط را تنظیم کنید.

این عملیات متعلق به مالک دسترسی فایل و ترمینال است و endpoint وب ندارد. همه نشست‌های حساب هدف، شامل نشست فعلی، با تغییر رمز ابطال می‌شوند؛ سفارش‌ها، فایل‌ها و حساب دیگر حفظ می‌شوند. تغییر hash، ابطال نشست و رخداد password_reset در یک تراکنش هستند. تغییر حساب حین تأیید با نسخه hash اولیه تشخیص داده می‌شود و دستور باید از ابتدا اجرا شود. پس از بازیابی وارد پنل شوید؛ مالکیت مهمانِ قدیمی خودکار به نشست تازه منتقل نمی‌شود.

پنج تست روی حساب موقت: ابطال تمام نشست‌های هدف و حفظ دیگران، رد نسخه قدیمی، ورودی نامعتبر/حساب ناشناخته، rollback و رد ورودی لوله‌شده یا آرگومان اضافی. فرمان تعاملی روی حساب واقعی اجرا نشده و رمز واقعی تغییر نکرده است. رفتار پوشاندن ورودی در ترمینال واقعی در این دور دستی بررسی نشده است.
